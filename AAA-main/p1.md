# Prompt #1 — Project Foundation & Vision (Do Not Write Gameplay Yet)

Copy everything below into Cline.

```text
# HERO OF ETERNIA
# PROMPT 1 OF 150
# PHASE 1 — PROJECT FOUNDATION

You are the complete development studio responsible for building a production-quality Android RPG from scratch.

Roles:
- Creative Director
- Game Director
- Lead Software Architect
- Senior Android Engineer
- Senior Game Programmer
- UI/UX Designer
- Environment Artist
- Character Artist
- QA Lead
- Security Engineer
- Performance Engineer
- DevOps Engineer
- Technical Writer

Your goal is NOT to build gameplay in this phase.

This phase establishes a professional foundation that every future phase will use.

==================================================
MAIN OBJECTIVE
==================================================

Create the complete project foundation for a large Android RPG called:

Hero of Eternia

The project must be scalable enough to support years of future development.

Do not create temporary solutions.

Everything must be production-ready.

==================================================
PROJECT GOALS
==================================================

Primary Platform

Android

Offline First

All player progress stored locally.

Support

Android 8+

ARM64

Landscape Mode

Touch Controls

Controller Ready

Tablet Ready

Future PC Port Ready

==================================================
ENGINE DECISION
==================================================

Evaluate Unity and Godot against these criteria:

- Android performance
- Rendering
- Asset ecosystem
- Tooling
- Long-term maintainability
- Community support
- Learning curve
- APK size
- Performance on low-end devices

Choose ONE engine and explain the decision.

Once chosen, use only that engine for the rest of the project.

==================================================
PROJECT STRUCTURE
==================================================

Design a scalable folder structure.

Example categories include:

Assets

Animations

Audio

Characters

Enemies

Bosses

Environment

Items

Materials

Prefabs

Scenes

Shaders

Scripts

UI

Fonts

Localization

Resources

StreamingAssets

Settings

Plugins

ThirdParty

Documentation

Tests

Editor

Build

Addressables (if applicable)

Provide the complete directory tree.

==================================================
SCRIPT ARCHITECTURE
==================================================

Design the architecture before writing gameplay code.

Define:

GameManager

SceneManager

SaveManager

AudioManager

SettingsManager

LocalizationManager

InputManager

ResourceManager

UIManager

QuestManager

InventoryManager

CharacterManager

CombatManager

WorldManager

NPCManager

AIManager

WeatherManager

TimeManager

PerformanceManager

EventBus

Dependency Injection approach (if used)

State machine strategy (if used)

Explain the responsibility of each system.

==================================================
CODING STANDARDS
==================================================

Create project-wide coding conventions.

Include:

Naming

Folders

Namespaces

Class organization

Comments

Error handling

Logging

Versioning

Documentation standards

Testing standards

Git commit style

Branch strategy

==================================================
LOCAL STORAGE
==================================================

The game must work completely offline.

Design the save architecture only.

Do not implement gameplay saves yet.

Plan storage for:

Player

Inventory

World

NPC

Quest

Achievements

Settings

Graphics

Audio

Statistics

World Seeds

Buildings

Crafting

Pets

Mounts

Future DLC compatibility

Support save version upgrades without losing player progress.

Explain the chosen storage format and why it fits this project.

==================================================
GRAPHICS STRATEGY
==================================================

Design a graphics quality system.

Include presets:

Low

Medium

High

Ultra

Explain how each preset changes:

Texture quality

Shadow quality

Lighting

Post-processing

View distance

Effects

Particles

Anti-aliasing

Automatically detect device capability at first launch and choose an appropriate preset.

==================================================
PERFORMANCE TARGETS
==================================================

Define measurable goals.

Examples:

Cold launch time

Average FPS

Peak memory

Battery usage

Maximum draw calls

Scene loading time

Target APK size

Explain why each target is realistic.

==================================================
SECURITY
==================================================

Design strategies for:

Save-file integrity

Basic anti-tampering

Error logging

Crash reporting hooks

Safe handling of local data

Do not add online account systems in this phase.

==================================================
DOCUMENTATION
==================================================

Create these markdown documents:

README.md

PROJECT_MEMORY.md

ARCHITECTURE.md

CODING_STANDARD.md

ROADMAP.md

CHANGELOG.md

KNOWN_LIMITATIONS.md

TEST_PLAN.md

Each document should contain meaningful initial content.

==================================================
TESTING
==================================================

Before considering this phase complete:

Review architecture.

Identify weak points.

List risks.

Suggest improvements.

Run a self-review.

Score:

Architecture

Scalability

Maintainability

Performance readiness

Documentation

Android readiness

Code quality

Security

Each score must include a short explanation.

==================================================
OUTPUT FORMAT
==================================================

Deliver:

1. Engine selection and justification.

2. Complete folder tree.

3. Architecture overview.

4. Responsibilities of every manager/system.

5. Coding standards.

6. Local storage design.

7. Graphics quality strategy.

8. Performance targets.

9. Security design.

10. Documentation contents.

11. Risk analysis.

12. Improvement recommendations.

13. Self-review with scores.

Do NOT create gameplay.

Do NOT create player movement.

Do NOT create UI.

Do NOT create combat.

Do NOT create inventory.

Do NOT skip any section.

Stop after this phase.

Wait for Prompt #2 before implementing anything else.
```

### Expected outcome of Prompt #1

By the end of this phase, you should have:

* A clear engine choice.
* A complete project architecture.
* A professional folder structure.
* Coding standards.
* Documentation files.
* A save-system design.
* Performance goals.
* Risk analysis.

Only after that foundation is complete should you move to Prompt #2, which will focus on creating the actual project and configuring the engine based on the approved architecture.
